# Riptide known-failure baseline.

# A NEW failure — one not listed here — means the change under review broke
# something, and the gate fails. A baseline entry that has started passing is
# reported as stale but does NOT fail the build: a passing test is not a
# regression, and timing-sensitive tests can pass on a quiet machine and fail
# under load, so failing on those would make the gate itself flaky.
#
# One failing pytest node ID per line, sorted (LC_ALL=C). Add a line only for a
# failure that is genuinely known and tracked; prefer fixing the test. Delete
# lines once they pass.
#

#
